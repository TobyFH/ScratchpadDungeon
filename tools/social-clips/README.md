# Scratchpad Dungeon social first cuts

Three vertical edits of real browser gameplay. Production `index.html` is read
only. Runtime-only fixtures set a legal reel build, level, wounds and encounter;
real `spin`, critical, enemy, movement, beacon and treasure handlers resolve it.
Outcomes are not composited numbers. The raw recordings retain startup frames;
render.py cuts these out. These are staged demonstrations, not candid runs.

## Outputs

`test-results/social-clips/final/{jackpot,gamble,dungeon}.mp4`:
1080×1920, 30 fps, H.264/yuv420p, AAC, fast-start MP4.
`source/*.webm` are original 1920×1080 recordings. Their JSON sidecars record
browser errors and real final roll receipts. `edit-manifest.json` records cuts,
source timings, captions and crop rectangles, plus ffprobe results.

## Re-edit

Install FFmpeg (including ffprobe) and Python 3; no Python packages are needed.
Run `python tools/social-clips/render.py` from the project root. Change EDITS
for source in/out points, crop regions and captions. It retains segment renders,
caption files and generated WAV mixes. Fonts are the game's OFL Cabin Sketch
and Caveat, with their licence files beside them. All footage is cropped to
specific UI regions, never a miniature full-screen game inside a vertical frame.
Paper framing and captions stay within central mobile-safe areas.

Audio is an original deterministic synthesized bass/pluck bed, reel-like clicks,
impacts and short reward chords generated by render.py. No online music, paid
services or uploaded recordings of unconfirmed promotional licensing are used.
The soundtrack is a postproduction mix, not a live system-audio recording.
The captured animations and outcomes are the actual game. Captions explain the
mechanic without sound. Uploaded game music can be substituted after its
promotional rights are confirmed.

## Re-capture (optional, Linux)

`npm ci` supplies Playwright; install Chromium and FFmpeg separately. Set
`PLAYWRIGHT_BROWSERS_PATH` to a writable cache. Playwright's ffmpeg build can be
installed with `npx playwright install ffmpeg`. In this cloud environment its CDN
was blocked, so the installed system FFmpeg was used compatibly:

```sh
export PLAYWRIGHT_BROWSERS_PATH="$PWD/test-results/playwright-cache"
mkdir -p "$PLAYWRIGHT_BROWSERS_PATH/ffmpeg-1011"
ln -sf /usr/bin/ffmpeg "$PLAYWRIGHT_BROWSERS_PATH/ffmpeg-1011/ffmpeg-linux"
node tools/social-clips/capture.cjs
# Or pass jackpot / gamble / dungeon to recapture one scenario.
```

Capture uses `/usr/bin/chromium`. Capture and rendering are separate so editing
never requires recording again. New captures may choose different species;
review their source timings and adjust EDITS before publishing. No production
balance, artwork, menus or progression are modified. Videos and intermediate
files are ignored by Git; only the small pipeline files belong in version control.

Review start/middle/end frames and listen to each full mix before posting. These
are initial first cuts for review, with no invented Steam store URL or claim.

## Delivery checks

Run `python tools/social-clips/verify.py` after rendering. This decodes every
frame, checks H.264/AAC and 1080×1920, enforces a 10–20 second duration, measures
volume, and extracts explicit start/middle/end review boards. The mix is
normalized toward −16 LUFS with a −1.5 dB true-peak limit. Inspect the JPG boards
and review the complete clips before posting; the source timing receipts are
not a substitute for watching the final edit.
